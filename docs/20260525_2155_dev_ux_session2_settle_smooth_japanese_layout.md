## ユーザ作業で見えた課題と対処

明日の実機テストに備えた dev GUI の改修ログ。 ユーザの指摘ごとに、 何を直したか / なぜそうしたかを列挙。

### 1. アーム凍結問題

**症状**: 速度 1 + 倍率 0.1 で長時間の Probe を続けると、 `actual XYZ` が同じ位置に張り付いて以降の MOVE L が全部失敗 → MOVE J も 30° 超えのまま timeout → 復旧不可。

**原因**: probe handler に hardcode していた `settle_s=4.0` が低速時の動作時間より短く、 アームがまだ動いている間に次の EndPoseCtrl が積み上がって SDK 内部キューが壊れた(N4 と同質の starvation)。

**対処** (Edit A):
- `_move_endpose` で `settle_s` を 「呼び出し値 と speed 適応値 (`30 / max(1, speed)`) の max」 として扱う
- 速度 1 では自動的に 30 秒待つ → アームが確実に終わってから次コマンド
- post-move dwell 0.4 秒も追加(end-of-motion 振動吸収)

### 2. CAN 接続が分かりにくい

**症状**: 「`EnablePiper timeout`」 だけだと TX 死 / アーム電源 OFF / master mode 残のどれか分からず、 ユーザがターミナルで `ip -s -d link show can0` を叩いて診断する必要あり。

**対処** (Edit before this session, kept):
- **ステータスバーに live CAN カウンタ** : `CAN:●UP TX:1234 RX:5678 err:0` を 2 秒ごと更新
- **TX が動かなければ赤に + `TX-DEAD` 表示**(USB-CAN 物理故障の即時判別)
- **Connect 失敗時に自動診断ダイアログ**: TX delta / RX delta / err count を見て 4 つのケースに分類:
  - `USB-CAN TX dead` → USB-CAN 抜き差し手順を表示
  - `Arm not responding` → アーム電源確認手順
  - `CAN bus errors` → 再 init 手順
  - `residual state` → Recover Connection ボタン提案
- **Recover Connection ボタン**: 0xFC release を 1 クリックで送る

### 3. UI 用語が意味不明

**症状**: 「Probe」 「Reach」 「MOVE L」 「pen-down」 「center_calc」 等の英語がエンジニア以外には不明。

**対処** (Edit B): UI 全文を日本語化
- ボタン: `接続` `ホーム/撮影位置へ` `収納ポーズへ` `切断` `接続をリセット` `左上 (TL)` `ペン下げ` 等
- セクション: `1. 接続` `1.5. リーチ確認` `2. キャンバスキャリブレーション` `3. ペン接触深さ調整` `3.5. キャンバス中央の微調整` `4. 正方形を描く`
- Phase 表示: `B1 四隅: 2/4 記録済み [左上, 右上] → 次: 右下`
- ステータス: `● 接続中 / ● 未接続 / マスターモード中 / (通常) / 関節 (マスター)`
- 警告: `⚠ アーム電源リセットが必要`

### 4. ログスペースが狭い

**症状**: 各セクションを縦に積んでログが下に押し出されて 12 行しか見えない。

**対処** (Edit C): 2 カラムレイアウト
- `ttk.PanedWindow` で水平分割: 左ペイン = 全セクション、 右ペイン = ログ(縦長)
- ウィンドウサイズを `1080x920` → `1600x920` に拡張
- 仕切りバーをドラッグして比率調整可

### 5. 中央が低い

**症状**: B1 で BR/BL が関節限界(margin 0.0°)で記録されたため、 4 隅平均中央 Z=315 が視覚的なキャンバス中央 (Z=370 ぐらい) より明らかに低い。

**対処** (Edit I): 関節限界張付の警告
- B1 で margin < 5° のコーナーを記録すると **即座にダイアログ警告**(取り直し推奨)
- phase 表示で 該当コーナー名に `⚠️` 付け、 ラベル全体を赤
- **保存時にもダイアログ**: 限界張付のコーナー一覧を表示して 「このまま保存しますか?」 確認

(`MARGIN_TIGHT_DEG = 5.0` で閾値定数化)

恒久的な解決は **B4 (中心微調整) で視覚中心を手動確定** すること(既に dev に実装済)。

### 6. 速度設定がほとんど効かない

**症状**: `関節速度 1` + `直線移動 倍率 0.1` でも MOVE L はあまり遅くならない。 GUI 灰色時間だけが長くなる。

**原因分析**:
- SDK の MOVE J(関節空間補間) は速度パラメータが効く → ホーム位置への移動は遅く滑らか
- SDK の MOVE L(cartesian 直線) は速度パラメータがあまり効かない(おそらく内部に最低速フロアがある)
- これは SDK / firmware 側の仕様 で、 アプリ側でどうにかするには代替手段が必要

**対処 1** (Edit D, 中間案): MOVE L の **チャンク化**
- 長距離の move を `chunk_mm` 刻みに分割し、 各間に `chunk_dwell` の停止
- 視覚的に「遅く」 見えるが、 ユーザフィードバック「動きが段階的でスムーズじゃない」 → 不採用

**対処 2** (Edit H, 安全側): チャンクを切替え式に
- `分割幅(mm)` Spinbox 追加(セクション 1)、 デフォルト 0 = 分割なし(スムーズ高速)
- カクカク低速が欲しいときだけ 5-20 に上げる

**対処 3** (Edit J, 実験): 位置決めを **MOVE J モード** で
- 「位置決めを関節補間 (低速で滑らか・実験)」 チェックボックス追加
- チェックすると `ModeCtrl(0x01, 0x01, speed, 0x00)` + `EndPoseCtrl(target)` で送信 → SDK が内部 IK して関節補間
- ホーム位置への移動と同じ滑らかさ + 速度パラメータが効くハズ(未検証)
- **描画ストロークは `force_move_l=True` で強制 MOVE L** にして直線軌道を維持

実機検証で 3 通りの動作モード のどれが実用的か確認する予定。

### 7. 「中央へ移動」 が自動でペン下げる

**症状**: `中央へ移動` ボタンが常に pen-down モードで実行 → 中央位置が悪い時にペン先がキャンバスを擦って傷が付く。

**対処** (Edit F): Section 3 の分離
- `中央へ移動 (ペン上げ)` で移動だけ
- 新規 `ペン下げ` ボタン: 中央到着後に手動で押す
- `ペン上げ` ボタン: 既存(押し付け状態を解除)
- 「中央へ移動 → 観察 → ペン下げ → X 微調整」 の流れになり意図が明確

### 8. 「撮影位置へ移動」 が欲しい

**対処** (Edit G): `ホーム位置へ` → **`ホーム/撮影位置へ`** に名前変更
- B2 設計判断 (chat 側) で `ready_pose = capture_pose` 同一運用が確定
- ボタン 1 個で 「撮影に使う位置」 と 「描画前後のホーム位置」 が同じだと明示
- 既存の `Record current as Ready/Capture pose` ボタン (B1 内) で記録した値が読まれる

## 明日の実機テスト計画

### 主目的: 「位置決め関節補間」 モードの動作確認

1. `Restart GUI` → セクション 1 に **`☐ 位置決めを関節補間 (低速で滑らか・実験)`** チェック
2. 接続 → ホーム/撮影位置へ → **中央へ移動**(ペン上げで止まる)
3. 動きを観察:
   - ✅ スムーズかつ低速 → ホーム位置への移動と同じ滑らかさ → **本命**
   - ⚠️ アーム動かず err 大 → SDK がモード不一致を拒否 → チェック外す
   - ❌ 暴走 → 緊急停止 + チェック外す
4. 関節速度 1-10 を変えて速度感を確認
5. ペン下げ → X 微調整 → 動作 OK か確認
6. (任意) 分割幅 5-10 で比較

### 副次的に検証したいこと

- B1 で意図的に BR/BL を関節限界まで攻めた時の警告ダイアログ表示
- B4 で対角線交点へ移動 → Z+ で視覚中心へ → 確定 → yaml 更新 → 再起動 → 中央が正しい位置に
- ステータスバーの CAN カウンタが TX/RX 動いているか
- 接続失敗時に自動診断ダイアログが出るか

### 既知の制約 (今日確認済み)

- BR/BL が関節限界に張り付くのはアームの kinematic envelope の物理的制約。 解決はキャンバスをアームの届く位置に移動 or B4 で中央を手動確定。
- SDK の MOVE L 速度パラメータは低速 (spd<5) で効きが悪い。 だから関節補間モードを試す価値があり。
