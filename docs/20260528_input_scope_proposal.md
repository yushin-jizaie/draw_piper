# 入力スコープ提案 (2026-05-28)

> ユーザフィードバック (2026-05-28 09:00):
> 「良さそうなのは B と F だけ。 そしてその 2 つはポーズがほぼ一緒。
> ユーザは必ずしも人間の顔を描くとは限らない」

これは構造的に正しい指摘。 本ドキュメントは「ユーザ入力をどうハンドリングするか」
の 3 段階の提案を出して、 選択肢を示す。

---

## 現状の問題分析

### 1. style ref が「松本タッチの男児」 固定
`IMG_4311.JPG` (花男表紙) を style ref に使っているので、 IP-Adapter は
「松本タッチの少年キャラ」 を attention に注入する。 結果:
- 入力が face なら 松本少年が出る (B/F)
- 入力が棒人間でも 松本少年に化ける (D)
- 入力が tree/dog/car などでも 松本少年に化ける (未検証だが推測)

### 2. seed 固定で pose ほぼ同じ
B (smiley) と F (angry) は表情が違う sketch でも、 似たような少年立ち姿 +
spiky 髪 が出る。 これは:
- seed=42 を 全試行で固定
- 同一 style ref (IMG_4311)
- IP-Adapter が pose を支配 (= base + ControlNet が弱まる)

### 3. 入力多様性 vs 「松本タッチ」 のトレードオフ
松本大洋 = 「人間キャラ + urban + animal」 等 多様な題材を描いている。 でも
1 つの style ref では 1 種類のタッチしか転写できない。 ユーザが多様なものを
描く前提なら、 style ref も多様に持つ必要がある。

---

## 3 レベルの解決案

### Level 1: 入力を「人間の顔/キャラ」 に限定する (最も簡単)

**やること**:
- UI / docs で 「描けるのは 人間の顔/キャラのスケッチ」 と 明示
- 顔以外を描いたら 「松本タッチではなく clean line art になります」 とフォールバック

**メリット**:
- 実装不要 (現状の pipeline で OK)
- 期待値管理が明確

**デメリット**:
- ユースケース大幅縮小 (「絵を描くロボット」 の魅力減)
- 動物/モノ/風景 を描くケースは未サポート

### Level 2: ユーザがカテゴリを選ぶ multi-mode 方式 (中程度)

**やること**:
1. UI に「描くもの選択」 ボタン (5-6 種類):
   - 👦 **キャラクター** (人間の顔・全身)
   - 🐱 **動物** (猫・犬・鳥)
   - 🏠 **建物・乗り物** (家・車・電車)
   - 🌳 **植物・自然** (木・花・葉)
   - ✨ **その他** (記号・抽象) — IP-Adapter off で clean lineart
2. 各カテゴリに 対応する style ref を 用意 (松本作品から curate):
   | カテゴリ | candidate ref |
   |---|---|
   | キャラ | IMG_4311 (花男表紙) |
   | 動物 | (新規 curate 要、 Sunny シリーズ等から) |
   | 建物 | IMG_4321 (ナンバーファイブ表紙、 街並) |
   | 植物 | (新規 curate 要) |
   | その他 | (IP-Adapter off で clean lineart) |
3. パイプライン: ユーザ選択カテゴリ → 対応 style ref を読み込んで two-stage 実行

**メリット**:
- ユーザの「描いたつもり」 と一致する style 適用
- 既存 two-stage パイプラインを minor 拡張で実現可
- 段階的に カテゴリ追加可能

**デメリット**:
- ユーザの UI 操作 1 ステップ増
- カテゴリごとに 松本作品から ref curate 要 (1-2 時間の作業)
- カテゴリ境界曖昧 (例: 「家を背景に立つ少年」 はどっち?)

### Level 3: VLM 自動分類 + 動的 style ref 選択 (高度)

**やること**:
1. ユーザは「描くもの選択」 なしで sketch だけ提供
2. 既存 Qwen2.5-VL (M8 で統合済) で input sketch を分類:
   ```
   VLM 出力例:
     {"category": "character", "description": "a young boy with messy hair",
      "subjects": ["face", "human"]}
   ```
3. style ref pool から VLM 分類結果に matching する ref を 自動選択
4. two-stage pipeline 実行

**メリット**:
- ユーザは描くだけで OK (UX 最良)
- 自動的に最適な style ref が選ばれる
- 将来 ユーザのスタイル好み学習 (個人最適化) にも拡張可

**デメリット**:
- VLM 推論時間 (~4 秒) + pipeline 通し 加算
- VLM の認識精度依存 (曖昧な sketch で誤分類リスク)
- 実装工数: VLM 出力 → ref 選択ロジック追加 (4-6 時間)

## 推奨

**段階展開**:
1. **今すぐ** (Level 1): docs/README に「現在のサポート範囲 = 人間の顔/キャラスケッチ」
   と明記
2. **次の improvement (1-2 日)** (Level 2): multi-mode で 「キャラ / 動物 / 建物 /
   その他」 の 4 カテゴリ展開。 各 style ref を松本作品から curate。
3. **理想形 (1 週後)** (Level 3): VLM 自動分類で UX 最適化

理由:
- Level 1 だけだと「絵を描くロボット」 の魅力欠ける
- Level 2 は 既存 two-stage の拡張で済み、 VLM 統合は将来でも遅くない
- Level 3 は VLM 統合工数 vs UX 向上の bench 次第

## Pose 多様化案 (Level に依らず適用可)

「seed=42 固定」 を解放するだけで pose が変わる。 以下を組み合わせ:

1. **seed をランダム化** (毎回違う pose になる、 ユーザは 数回生成して気に入った
   ものを選ぶ — 「ガチャ的 UX」)
2. **style ref を ランダム選択** (同カテゴリ内で 数枚を rotate、 pose 分散)
3. **prompt に動作 keyword 追加** ("standing" / "running" / "sitting" /
   "looking up" を ランダム or ユーザ選択)

最低限: seed のみランダム化が 1 行 fix で済む。
