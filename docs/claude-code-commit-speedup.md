# Claude Codeのcommit/pushを高速化するTips

Claude Codeにgit commit & pushを依頼すると時間がかかる問題への対処メモ。

## 遅くなる主な原因

| # | 原因 | 詳細 |
|---|------|------|
| 1 | `git status` / `git diff` の全件解析 | 変更ファイルが多いと解析だけで時間を食う。`node_modules`やビルド成果物が`.gitignore`漏れしてると致命的。 |
| 2 | コミットメッセージの吟味 | 変更内容を読み直して丁寧に書こうとする。大規模差分だと数十秒〜。 |
| 3 | pre-commitフック | lint / test / format などが裏で走る。 |
| 4 | 認証チェック | `gh` CLI や auth まわりの確認で待たされる。 |
| 5 | モデルの思考時間 | 「適切なメッセージを考える」工程が人間より長い。 |

## 解決策

### すぐ効く

- **コマンドを直接渡す**
  ```bash
  git add . && git commit -m "fix: xxx" && git push
  ```
- 「差分確認はスキップして既存のスタイルでサクッとコミットして」と指示
- コミットメッセージを自分で渡して、Claudeには実行だけさせる

### `CLAUDE.md`に書いておく

```markdown
## Git運用ルール
- コミット時は差分の詳細解析をスキップ
- 簡潔な1行メッセージで(必要な場合のみbody追加)
- pre-commitフックは尊重するが、再試行は1回まで
```

### 中長期で効く

- `.gitignore`の見直し(ビルド成果物・キャッシュ・ログを除外)
- pre-commitフックの軽量化、または `--no-verify` の許可
- `/compact` や新セッションで履歴を軽くしてから依頼

## 一番効くやつ

> **「考える工程は自分で持つ」**
>
> コミットメッセージを自分で書いて、Claudeには実行だけ任せる。
> 3プッシュ感覚に一番近い。
